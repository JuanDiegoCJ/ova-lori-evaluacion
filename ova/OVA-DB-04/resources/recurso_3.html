Contexto y Motivación

Introducción al Caso Real

Imagina que Oracle es un edificio: los datafiles son los cimientos físicos y los tablespaces, las habitaciones lógicas donde se guardan los datos. Sin esta separación, administrar el espacio sería caótico.

Despliega cada sección para avanzar en la lectura y comprobar respuestas.
Idea Central

Oracle separa la estructura lógica (tablespace, segmento, extensión, bloque) de la física (datafiles). El tablespace agrupa objetos lógicos, mientras que el datafile es el archivo real en disco.

Ejemplo Razonado (Oracle)

Crear un tablespace 'TBS_DATOS' con un datafile 'datos01.dbf' de 100 MB. Lógicamente, puedes crear tablas; físicamente, los datos se escriben en ese archivo.

Comprobación de Aprendizaje

¿Cuál es la diferencia fundamental entre un tablespace y un datafile?

Respuesta modelo fundamentada:

El tablespace es lógico y agrupa segmentos; el datafile es físico y almacena los datos en disco. Un tablespace puede tener varios datafiles.

Idea Central

La jerarquía es: tablespace → segmento → extensión → bloque. Cada tabla o índice ocupa un segmento, formado por extensiones de bloques contiguos.

Ejemplo Razonado (Oracle)

La tabla 'empleados' crea un segmento en TBS_DATOS. Al insertar datos, Oracle asigna extensiones de 64 KB, compuestas por bloques de 8 KB.

Comprobación de Aprendizaje

¿Qué relación existe entre un segmento y una extensión en Oracle?

Respuesta modelo fundamentada:

Un segmento es un conjunto de extensiones. Cada extensión es un grupo de bloques contiguos que se asigna para almacenar datos del segmento.

Idea Central

Se crea un tablespace con `CREATE TABLESPACE`, especificando datafiles y tamaño. Luego se asigna a un usuario con `ALTER USER ... DEFAULT TABLESPACE`.

Ejemplo Razonado (Oracle)

CREATE TABLESPACE tbs_app DATAFILE 'tbs_app01.dbf' SIZE 50M; ALTER USER juan DEFAULT TABLESPACE tbs_app; Así, las tablas de Juan usan ese espacio.

Comprobación de Aprendizaje

¿Qué comando crea un tablespace con un datafile de 100 MB?

Respuesta modelo fundamentada:

CREATE TABLESPACE tbs_ejemplo DATAFILE 'tbs_ej01.dbf' SIZE 100M; Esto define el archivo físico y su capacidad inicial.

Idea Central

Cada usuario tiene un tablespace por defecto y uno temporal. Asignarlos correctamente evita saturar el tablespace SYSTEM y optimiza el rendimiento.

Ejemplo Razonado (Oracle)

ALTER USER ana DEFAULT TABLESPACE tbs_app TEMPORARY TABLESPACE temp; Así, las operaciones de ana usan tbs_app y las temporales usan temp.

Comprobación de Aprendizaje

¿Por qué es importante asignar un tablespace de usuario distinto de SYSTEM?

Respuesta modelo fundamentada:

Para evitar mezclar datos de usuarios con el diccionario de datos, reduciendo fragmentación y riesgos de llenado del sistema.

Idea Central

Las vistas DBA_DATA_FILES y DBA_SEGMENTS muestran el tamaño de datafiles y los segmentos por tablespace. Permiten monitorear el uso y planificar crecimiento.

Ejemplo Razonado (Oracle)

SELECT file_name, bytes FROM DBA_DATA_FILES WHERE tablespace_name='TBS_APP'; Con DBA_SEGMENTS, consulta tablas y su espacio ocupado.

Comprobación de Aprendizaje

¿Qué vista usarías para saber cuánto espacio ocupa una tabla en un tablespace?

Respuesta modelo fundamentada:

DBA_SEGMENTS, filtrando por segment_name y tablespace_name. Devuelve bytes ocupados por el segmento de la tabla.

Aplicación Concreta para el DBA (Oracle)

Como DBA, crea tablespaces con `CREATE TABLESPACE tbs_ventas DATAFILE 'ventas01.dbf' SIZE 200M AUTOEXTEND ON NEXT 10M;` y consulta `DBA_DATA_FILES` para verificar tamaño. Usa `DBA_SEGMENTS` para detectar tablas que consumen demasiado espacio.

Buenas prácticas del DBA: Consulta periódicamente el diccionario de datos y las vistas de rendimiento dinámico (V$ y DBA_*) para auditar el impacto en memoria y almacenamiento.

Dominar tablespaces y datafiles permite gestionar el almacenamiento lógico y físico de forma eficiente, asegurando disponibilidad y control del crecimiento en Oracle.
