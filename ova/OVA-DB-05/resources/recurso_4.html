Selecciona un bloque del diagrama para ver su función.

  1. La aplicación realiza una consulta SELECT a Azure SQL, abriendo una conexión a través de la puerta de enlace.
  2. La puerta de enlace autentica y enruta la consulta al motor de base de datos en la réplica primaria.
  3. El motor inicia una transacción y el gestor de transacciones elige el nivel de aislamiento. Para alta concurrencia, se usa Read Committed Snapshot Isolation (RCSI).
  4. El gestor de bloqueos evalúa si puede leer la versión anterior (sin bloquear) o si necesita bloqueo exclusivo. La operación se ejecuta sobre el almacenamiento.

Para que todos los recursos de hardware estén centralizados en un solo servidor.Porque el control fino de acceso a filas debe ocurrir lo más cerca posible del almacenamiento de datos.Para que solo los administradores puedan configurar los bloqueos.Para que los clientes puedan modificar los bloqueos directamente. La jerarquía desde el cliente hasta el almacenamiento permite aislar responsabilidades: la puerta de enlace gestiona el acceso, el motor optimiza y el gestor de bloqueos resuelve la concurrencia en el nivel más fino.
